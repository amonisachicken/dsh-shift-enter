# Shift+Enter 发送

把 Web 界面消息输入框的发送键位改成 **Shift+Enter 发送、Enter 换行**，这样单独按一次 Enter 只会换行，不会误把消息发出去。改动作用于当前 profile 的每一个会话。

## 行为

| 按键 | 行为 |
| --- | --- |
| Shift+Enter | 发送消息（与原来的 Enter 相同：繁忙时按“繁忙时的发送行为”设置排队或插话） |
| Enter | 在当前草稿中换行 |
| Cmd/Ctrl+Enter | 仍然使用另一种投递方式（排队／插话），不受影响 |
| 输入法组字时的 Enter | 仍然交给输入法确认候选词，不发送、不强制换行 |

斜杠指令与 `@` 引用菜单打开时，菜单仍用自己原有的 Enter / Tab 选择方式。

## 生效范围

- 所有会话的主输入框，以及首页输入框。
- 快捷键总览（`Cmd/Ctrl+/`）中“发送消息”和“换行”两行会显示交换后的键位。
- 通过 Conversation 插件的实时键位策略生效；禁用或移除本插件后立即恢复默认键位（Enter 发送、Shift+Enter 换行），不需要改代码。

## 依赖 DSH 补丁

DSH 原本把「Enter 发送 / Shift+Enter 换行」写死在 `@deepseek-ai/dsh-client-ui-conversation` 的输入框 keymap 里，插件无法从外部改。本仓库的 `dsh-patch/` 给该包加了一个实时可切换的发送手势策略（默认行为不变），`install.sh` 会给 DSH 源码打上补丁并重建该包的客户端产物。

插件检测不到这个 API 时**安全空操作**：不报错、不改键位。所以只安装插件而不打补丁，界面不会有任何变化。

## 限制

- 仅改变消息输入框的发送／换行映射；排队消息的行内编辑、目标栏、问答面板、终端等控件保留各自原有的 Enter 行为。
- 不改变发送、排队、插话、附件上传本身的逻辑，也不改变桌面端外壳的全局快捷键。
- 补丁针对 DSH 0.2.2-rc.3 的源码；DSH 升级后补丁可能冲突，重跑 `install.sh` 会提示。
